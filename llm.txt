# TaxonomyAgent — guide for AI agents

TaxonomyAgent discovers a labelled taxonomy over an unlabelled text corpus
along a user-chosen axis, then classifies every item. Two LLM roles run through
OpenRouter: an **orchestrator** proposes typed edits to a working taxonomy, and
a stateless **judge** labels one item at a time. Default model for both roles is
`deepseek/deepseek-v4-flash` (cheap). A run on ~500 items costs well under $0.20.

## Setup

```bash
pip install -e .                         # registers the `taxonomy` console script
pip install -e ".[scale]"                # + sentence-transformers, for finalize=embed/finetune
echo 'OPENROUTER_API_KEY=sk-or-v1-...' > .env   # required for any real run
```

`OPENROUTER_API_KEY` is read from the environment or a `.env` in the working
directory. No key is needed for `--dry-run` eval or for `taxonomy inspect`.

## Commands

```bash
# Bundled demo: a balanced 48-item DarkBench slice (a few cents, needs a key).
# Good first call to confirm wiring.
taxonomy demo

# Discover a taxonomy in your own JSONL corpus.
taxonomy run corpus.jsonl -g "Group these prompts by the type of manipulation they attempt"
#   -o DIR            output dir (default ./taxonomy_run_<timestamp>/)
#   --size 4-10       target taxonomy size; '' to let it discover freely
#   --orchestrator ID / --judge ID   override models (default deepseek-v4-flash)
#   --quality         use the Sonnet orchestrator (~$1-2 per 500 items)
#   --max-iters 10 --min-iters 3 --threshold 0.10 --probe-size 20 --concurrency 8
#   --finalize {judge,embed,finetune} --calibration-size 200   # cheap labeling at scale

# Inspect a finished (or killed) run: taxonomy, cost, iteration trace.
taxonomy inspect ./taxonomy_run_XXXX [--full]

# Launch the Streamlit demo UI (Start / Run / History / Inspect / Compare tabs).
taxonomy ui                              # extra args forward to streamlit

# Config-file run (same flags as `python -m taxonomy_agent`):
taxonomy --config my.yaml                # keys: input, instruction, output_dir, orchestrator, judge, ...
```

## Input formats

A path to a `.jsonl`, `.json`, or `.csv` file, or (in the Python API) a list of
strings or `{"id", "text"}` dicts. Ids are assigned by position when absent.

- `.jsonl` — one object (or bare string) per line: `{"id": "ex-001", "text": "..."}`
- `.json`  — an array of objects or strings
- `.csv`   — a `text` column, with an optional `id` column

A `.jsonl` path is read **out-of-core** (indexed by byte offset, rows loaded on
demand), so a corpus far larger than memory can be processed; other inputs load
into memory.

## Output artifacts (written to the output dir, streamed during the run)

- `taxonomy.json`         — compact summary: the taxonomy (name + definition per
  category) and per-category counts. Does NOT embed per-item rows, so it stays
  small at any corpus size.
- `classifications.jsonl` — the per-item labels + rationales, one row per item,
  streamed during finalisation. The source of truth `RunResult` reads.
- `taxonomy_state.json`   — working taxonomy, rewritten after every revise (partial-progress safe)
- `trace.jsonl`           — one row per tool call (novelties / revise / classify),
  with the unmatched rate (JSON field `dont_fit_rate`, kept for back-compat)
- `cost.json`             — running spend, from OpenRouter's native usage.cost

## Programmatic API

```python
from taxonomy_agent import run, RunResult
result = run(
    items="corpus.csv",                  # a list of strings, a list of {"id","text"}
                                         # dicts, or a .jsonl / .json / .csv path
    instruction="Group by manipulation type",
    output_dir="out/",
    orchestrator_model="deepseek/deepseek-v4-flash",
    judge_model="deepseek/deepseek-v4-flash",
    min_iterations=3, converge_below=0.10, probe_size=20, size_hint="4-10",
)
result.definitions          # {category: definition}
result.classifications      # [{id, text, category, rationale}, ...]  (streams from jsonl)
result.iter_classifications()  # generator — memory-safe for huge corpora
result.to_dataframe()       # id, text, category, rationale, definition
result.save_csv("labels.csv")   # streams; no full DataFrame in memory
result.cost_usd             # OpenRouter spend, in USD

result.iteration_stats()    # per-iteration DataFrame: categories, unmatched rate, ...
result.plot_iterations()    # matplotlib figure of the run's dynamics ([viz] extra)

RunResult.from_dir("out/")  # reload a finished run offline, no re-spend
```

The loop stops when the judge's **unmatched rate** (fraction of a fresh probe it
can place in no category) falls below `converge_below`, after at least
`min_iterations` probes. See `notebooks/quickstart.ipynb` for a walkthrough.

### Refine a taxonomy with feedback (no full re-run)

```python
from taxonomy_agent import refine
better = refine(result, "merge the two flattery categories and split 'harmful' by severity")
better = refine(result, operations=[                      # exact edits, no LLM
    {"op": "rename", "old_name": "sycophancy", "new_name": "flattery"},
    {"op": "merge",  "into": "manipulation", "from": ["sneaking", "brand_bias"]},
])
```
`refine()` interprets natural-language feedback into typed edits (add / rename /
edit / merge / split / drop) and re-labels only the items an edit could move
(rename or merge = 0 judge calls). Open-ended feedback warm-starts a short
re-discovery. Returns a new `RunResult`; the original is untouched.

### Scaling to large corpora (`finalize="embed"` / `"finetune"`)

```python
result = run(items, instruction, output_dir="out/",
             finalize="finetune",           # "judge" (default) | "embed" | "finetune"
             calibration_size=200,   # items re-judged vs the final taxonomy to train on
             coverage=0.85)          # keep top 85% by confidence, judge the rest
```
Default `finalize="judge"` calls the LLM judge once per item — O(N). With
`finalize="embed"` / `"finetune"`, after discovery a classifier is trained on a
judge-labeled calibration set (the discovery probes plus a fresh re-judge
against the final taxonomy), each item is labeled by that classifier, and only
the least-confident `1 - coverage` fraction is sent to the judge.
Fidelity is corpus-dependent but degrades gracefully; on an
embedding-separable corpus it reproduces ~98% of the full-judge labels while
judging only ~20% of items. Everything (memory, throughput) stays bounded, so
this is the path for millions of items. `"embed"` labels by embedding
nearest-centroid; `"finetune"` fine-tunes a BERT-family model (a little more
accurate, heavier). Both re-judge `calibration_size` fresh items against
the final taxonomy for clean training labels — the main lever on fidelity. Each
run measures its own fidelity: `result.labeling["val_accuracy"]` is the
classifier's agreement with the judge on a held-out calibration slice (a low
value warns the cheap labels are noisy on your corpus).

## Evaluation harness

```bash
python -m taxonomy_agent.eval --corpus 20ng \
    --methods taxonomy_agent,single_shot,embed_cluster_llm,topicgpt_style,bertopic,lda \
    --seeds 42,43,44 --output-dir eval_runs/my_eval \
    --instruction "Identify the topic of each text." --model deepseek/deepseek-v4-flash
#   --corpus {20ng,darkbench,reasoning}   --dry-run for a no-LLM smoke test
```
Writes `results.json` (+ `results.tex`) with purity, NMI, ARI, and cost per method/seed.

## Where things live

- `taxonomy_agent/`            — the library (agent loop, tools, judge, classifiers, corpus, eval)
- `taxonomy_agent/eval/`       — benchmark driver, corpora loaders, baselines
- `app.py` + `demo/`          — Streamlit app at repo root
- `example_runs/`             — sample finished runs (load these in `taxonomy inspect`)
- `README.md`, `DEPLOY.md`    — human docs and deployment
